 # DayFlow HRMS (AlgoNinjas)

 A full‑stack HRMS (Human Resource Management System) with role-based access for **Admin/HR** and **Employees**.
 It supports employee management, attendance tracking (check-in/out + breaks), leave management, payroll generation, and notifications.

 ## Tech Stack

 - **Client**
   - React + Vite
   - React Router
   - Axios
 - **Server**
   - Node.js + Express
   - MongoDB + Mongoose
   - JWT authentication
   - Nodemailer (email/OTP)
   - Cloudinary (leave attachments)

 ## Core Features

 ### Authentication & Security

 - **Sign up / Sign in** with email + password (and `employeeId` during signup)
 - **Role-based access control**
   - Admin/HR-only routes are protected via server middleware
 - **Email verification (OTP)** flow (can be disabled via env)
 - **Forgot password + Reset password (OTP)**

 ### Employee Management (Admin/HR)

 - Create employee users
 - View employee list
 - View and edit employee details
   - Personal profile fields (includes address)
   - Salary structure (earnings + deductions)
   - Bank details
   - Documents metadata

 ### Employee Self Profile

 - View own profile
 - Update own profile
 - Upload profile picture

 ### Attendance

 - Employee actions
   - Check-in
   - Break start / break end (supports multiple breaks)
   - Check-out
   - View own attendance
   - View monthly attendance
 - Admin/HR views
   - List attendance records (day/week filters)
   - View "present employees" by date
   - Weekly summary graph (present counts per day)
   - Filter attendance by employee

 ### Leaves

 - Employee actions
   - Apply leave (Paid / Sick / Unpaid)
   - Upload attachment (stored via Cloudinary)
   - View my leave requests
 - Admin/HR actions
   - View all leave requests
   - Approve / Reject leave
   - Leave approval can update attendance status to `Leave`
   - Leave approval checks available balance for Paid/Sick leaves

 ### Payroll

 - Employee actions
   - View my payroll
 - Admin/HR actions
   - List payroll entries
   - Generate payroll for a user (by month)
   - Generate payroll for all users (by month)

 ### Notifications

 - Employee actions
   - View my notifications
   - Mark notification as read
 - Admin/HR actions
   - Broadcast alerts to all employees
   - Send alert to a specific user
   - Supports in-app notifications + email delivery

 ## Workflows

 ### Admin / HR Workflow

 1. **Sign in** as Admin/HR.
 2. **Create employees** (or manage existing employees).
 3. **Manage employee details**
    - Salary components, bank details, documents, address.
 4. **Attendance monitoring**
    - View present employees for a day.
    - View day/week attendance records and filter by employee.
    - Review weekly summary graph.
 5. **Leave approvals**
    - Review requests.
    - Approve/Reject (approved leaves reflect in attendance; Paid/Sick checks leave balance).
 6. **Payroll generation**
    - Generate monthly payroll for a user or all employees.
 7. **Send notifications**
    - Broadcast alerts or notify a single employee (in-app + email).

 ### Employee Workflow

 1. **Sign in** as Employee.
 2. **Daily attendance**
    - Check-in
    - Break start/end
    - Check-out
 3. **View attendance** (daily + monthly).
 4. **Apply for leave** (optional attachment).
 5. **View leave requests** and status.
 6. **View payroll** once generated by Admin/HR.
 7. **Read notifications** and mark them as read.

 ## Getting Started (Local Setup)

 ### Prerequisites

 - Node.js (recommended: LTS)
 - MongoDB connection string (local MongoDB or Atlas)

 ### 1) Server Setup

 1. Install dependencies:
    - `npm install` (inside `server/`)
 2. Configure environment variables:
    - Create/update `server/.env`
 3. Start server:
    - `npm run dev`

 Server runs on: `http://localhost:4000`

 ### 2) Client Setup

 1. Install dependencies:
    - `npm install` (inside `client/`)
 2. Start client:
    - `npm run dev`

 Client runs on the Vite port shown in terminal (usually `http://localhost:5173`).

 ## Environment Variables (Server)

 The server uses `server/.env`. Common variables used by the codebase:

 - `PORT` (default `5000`)
 - `MONGODB_URI` (Mongo connection string)
 - `CORS_ORIGIN` (frontend origin; set to the Vite URL for strict CORS)
 - `JWT_SECRET` (JWT signing secret)

 Email / OTP:

 - `DISABLE_EMAIL_VERIFICATION` (`true`/`false`)
 - `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`
 - `SENDER_EMAIL`
 - `ADMIN_SIGNUP_SECRET` (required to create admin accounts via signup)
 - `HR_SIGNUP_SECRET` (optional; falls back to `ADMIN_SIGNUP_SECRET`)
 - `DEMO_ALLOW_EMPLOYEE_SIGNUP` (`true`/`false`)

 Cloudinary (leave attachments):

 - `CLOUDINARY_CLOUD_NAME`
 - `CLOUDINARY_API_KEY`
 - `CLOUDINARY_API_SECRET`

 ## Demo Data Seeding

 The backend includes a demo seed script:

 - Run:
   - `npm run seed:demo` (inside `server/`)

 Optional env vars for seeding:

 - `SEED_MONTH` (format `YYYY-MM`, default: `2026-01`)
 - `SEED_PASSWORD` (default: `Password@123`)
 - `SEED_COUNT` (default: `20`)

 After seeding, demo employees like `demo001@hrms.local` will exist with the seed password.
